# [`plot3d()`](https://tractoverse.github.io/rtists/reference/plot3d.md) method for `fiber::streamline` objects

Renders a single
[fiber::streamline](https://tractoverse.github.io/fiber/reference/streamline.html)
as an interactive 3D line plot. See
[`plot3d()`](https://tractoverse.github.io/rtists/reference/plot3d.md)
for the full parameter documentation and examples.

## Arguments

- x:

  A
  [fiber::streamline](https://tractoverse.github.io/fiber/reference/streamline.html)
  object.

- color:

  Controls how streamline colours are assigned. Accepted values:

  - `"orientation"` (default): per-point RGB colour derived from the
    local fibre direction. The absolute values of the normalised tangent
    vector \\(\|dx\|, \|dy\|, \|dz\|)\\ are mapped to the R, G, B
    channels — the standard DTI colour convention (left-right = red,
    anterior-posterior = green, superior-inferior = blue).

  - A **metadata key**: a string matching a key in `@point_data`
    (per-point scalar) or `@streamline_data` (per-streamline scalar,
    broadcast to all points). Numeric values are mapped to a continuous
    colour scale (`palette`); character values are coloured
    categorically.

  - A **CSS/hex colour string**: e.g. `"#E69F00"` or `"steelblue"`. All
    lines are drawn in that fixed colour.

- palette:

  A [plotly](https://rdrr.io/pkg/plotly/man/plotly.html) / ColorBrewer
  colour scale name applied when `color` is a numeric metadata key.
  Defaults to `"Viridis"`.

- backend:

  Character. Which htmlwidget renderer to use: `"threejs"` (default) or
  `"plotly"`. The three.js backend supports real world-space line
  thickness (true 3D tubes) and object-level depth-sorted transparency;
  the plotly backend is an opt-in alternative for interactive
  plotly-style charts.

- linewidth:

  Numeric. Width of the plotted lines. Defaults to `2`. On the three.js
  backend this maps to `THREE.LineBasicMaterial.linewidth`, which WebGL
  caps at `1` on most platforms; use `radius` for genuinely thick
  fibres.

- radius:

  Numeric radius in world units (three.js backend only). This is the
  knob for **true 3D tubes**; there is no separate `thickness` argument.
  radius is treated as data carried on the object: when `radius` is
  `NULL` (the default), a `radius` key in the streamlines' `@point_data`
  (per-point) or `@streamline_data` (per-streamline) is picked up and
  rendered as real 3D tubes; tubes are drawn exactly at that radius,
  never shrunk to avoid overlap between neighbouring fibres (overlap is
  the generator's business, not rtists's). An explicit `radius` argument
  overrides any data. Accepts:

  - `NULL` (default): draw at the object's own radius data if present,
    otherwise thin lines (fast `Line2` at `linewidth`).

  - A scalar `0`: fast flat `Line2` at `linewidth` (nothing needs a
    tube).

  - A positive **scalar**: every streamline is drawn as a real 3D
    `TubeGeometry` tube of this constant world radius, with genuine
    thickness, Phong flat shading, and object-level depth-sorted
    transparency (each tube is its own mesh sorted back-to-front).

  - A **per-streamline vector** (length == number of streamlines): one
    constant radius per line, drawn as `TubeGeometry`.

  - A **per-point vector** (length == total number of points): radius
    varying along each streamline, drawn as `TubeGeometry` with radial
    displacement — the most general form.

- opacity:

  Numeric in \[0, 1\]. Global line opacity. Defaults to `0.5`.

- bg:

  Background colour (CSS) of the scene (three.js backend only). Defaults
  to `"#111111"`.

- tooltip:

  Hover tooltip on the three.js backend. When a point of a streamline is
  hovered, an in-scene tooltip shows that bundle's name, the point's 3D
  coordinates, and the values of its attributes. Accepted values:

  - `TRUE` (default): show the bundle name (when the object carries
    one), the coordinates, and **all** attributes recorded on the object
    (per-point, per-streamline, per-bundle and per-bundle-set alike).

  - `FALSE`: disable the tooltip entirely.

  - A character vector of attribute column names: show only those,
    alongside the always-included coordinates (and bundle name when
    present). Names that do not exist on the object are ignored.

  Right-clicking the hovered tooltip opens a checkbox list of every
  toggleable column; ticking or unticking one updates the visible box
  immediately. The bundle name and coordinates stay pinned and cannot be
  toggled off.

  The plotly backend ignores this argument (the plotly surface carries
  its own hover).

- ...:

  Additional named arguments. Only the plotly backend uses these,
  forwarding them to `plotly::layout()` (e.g. `title = "My bundle"`);
  the three.js backend (default) ignores them.

## Value

An interactive htmlwidget (three.js or plotly, see
[`plot3d()`](https://tractoverse.github.io/rtists/reference/plot3d.md)).

## See also

[`plot3d()`](https://tractoverse.github.io/rtists/reference/plot3d.md)

## Examples

``` r
library(fiber)

# A single fibre curving through 3-D space, sampled densely into small
# steps, thin like a real DTI tract rather than a coarse polyline.
t   <- seq(0, 4 * pi, length.out = 200)
pts <- cbind(
  X = seq_len(200) * 0.1,
  Y = 0.5 * sin(t),
  Z = 0.5 * cos(t)
)
sl <- streamline(
  points          = pts,
  point_data      = list(FA = 0.4 + 0.3 * sin(t / 2)),
  streamline_data = list(mean_FA = 0.5)
)

# Colour by local fibre orientation (default), by per-point FA, or by a
# fixed hue.
plot3d(sl)
```
